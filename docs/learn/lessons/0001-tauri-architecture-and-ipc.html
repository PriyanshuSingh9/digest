Lesson 0001 Digest Engine Workspace

Tauri v2 Architecture & The IPC Bridge

Understand the two-process runtime model and how frontend React talks to Rust.

1. The Two-Process Mental Model

Unlike traditional Electron apps that ship a heavyweight bundled Chromium browser and Node.js runtime, Tauri v2 uses a lightweight, secure two-process model:

Frontend (Webview)

React 19 + TypeScript

Runs inside the OS native webview (WebKitGTK on Linux). Renders the UI, presentation slides, and user controls.

⚡ IPC Bridge ⚡ invoke() ➔ emit() / listen()

Backend (Tauri Core)

Compiled Rust Binary

Runs with native OS privileges. Manages audio playback, file caching, persistent state, and system APIs.

Why This Matters for Digest

In the Digest AI Article Engine, the UI needs to maintain 60 FPS visual synchronization with audio. Heavy tasks (audio generation, network fetching, token processing) run in the Rust backend without blocking the React render thread.

2. How the IPC Bridge Works

The frontend cannot directly access native OS resources (like reading random disk files or spawning threads) for security. Instead, it communicates through two primary IPC channels:

  1. Commands (invoke): A request-response Remote Procedure Call (RPC). The frontend asks Rust to do something and awaits a serialized JSON result.
  2. Events (emit & listen): A pub/sub channel. Rust can continuously stream events (e.g., audio clock timestamps) to the frontend.

3. Concrete Code Walkthrough

Let's look at the default boilerplate in your repository:

Rust Command Definition (src-tauri/src/lib.rs) 

#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {}! You've been greeted from Rust!", name)
}

pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .invoke_handler(tauri::generate_handler![greet])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

Frontend Invocation (src/App.tsx)

import { invoke } from "@tauri-apps/api/core";

// Inside a React component:
async function greetUser() {
  // Arguments are passed as a JSON object matching the Rust parameter names
  const response = await invoke<string>("greet", { name: "Learner" });
  console.log(response);
}
